# Vulkan backend architecture

The backend targets Vulkan **1.4**, Space Engineers **1.210.014**, x64 Windows Pulsar Legacy/net48 and Interim/net10, and native Linux Interim/net10 with LinuxCompat SDL3. It is experimental. A compiled handler or observed draw is separate from visual acceptance.

## Startup and recovery

The namespace-free `Preloader` validates the original `MyProgram.InitializeRender` signature and IL SHA-256, then replaces only the DX11 constructor with a stack-compatible factory call. Dedicated and force-null branches retain their original behavior. Pulsar lazy preloader caching is disabled in memory before patches; incompatible signatures leave DX11 intact. The preloader finish hook stays BCL-only. Bootstrap Harmony hooks install idempotently at the factory after platform/filesystem initialization and before renderer/device creation; installing them earlier can poison the game's render-settings initializer. Display patches use a separate runtime category.

After the game initializes its filesystem, `BackendFactory` reads `Storage/Vulkan.cfg`, checks enabled plugins and the platform integration, validates native assets/ABI, probes loader and device API/features, and returns `MyVulkanRender` or the vanilla DX11 renderer. The persisted vanilla renderer key remains DX11; the early renderer identity hook exposes Vulkan while active.

The requested backend is independent of the active backend. A Display screen owns its draft. Cancel, rejected resolution confirmation, and confirmation timeout preserve the prior backend. OK commits after successful confirmation. The selector and plugin configuration report that a restart is required; changing it does not close an active world.

A session journal is created before Vulkan activation and retained for the entire Vulkan session. Startup draw evidence is kept in memory. Only a graceful shutdown after that evidence clears the journal. An incomplete session or active failure persists DX11 recovery while preserving the requested Vulkan choice. Explicit retry acknowledges recovery. A scoped integration bypasses Pulsar Legacy's forced-kill exit prefix while Vulkan is active so the base game can dispose the renderer. Native failures after activation propagate through the game's controlled render-thread shutdown; the backend does not create a DX11 device during that session.

Enabled DX11 renderer consumers trigger a DX11 launch with their identities in the report. Their already-collected preloader hooks are not removed. Use a separate Pulsar profile containing Vulkan, LinuxCompat where required, and compatible gameplay plugins.

Anomaly core is allowed when its assembly references neither `VRage.Render11` nor SharpDX. A pack that publishes the dual-renderer handshake (`RouteTypeName` = `ClientPlugin.Backend.RendererRoute`, plus static `AllowDx11Device` and `AllowGuestWork`) may reference those assemblies: that reference is its closed DX11 path, and startup does not treat it as a conflict. `AllowDx11Device` is true only when the operational renderer is DX11. An assembly that references Render11 or SharpDX without that handshake still keeps the launch on DX11. During a Vulkan session Anomaly submits guest packets; native `guest_replay` at the six frame marks records nothing when that list is empty, so stock CPU work is unchanged. ABI stays version 1.

## Managed and native ownership

`MyVulkanRender` implements `IMyRender`; it keeps the game's render proxy, update/render frames, shared billboard batches, visible object output, pooled messages, output queue and actor IDs. A retired update frame processes state changes once and disposes each nonpersistent message once. Draw commands replay while retained; child command ownership remains with the outer message. Native packets contain copied arrays and primitive values; the engine never retains a pooled message or unpinned managed address.

`VulkanScene` reuses API-neutral `MyScene`, `MyActor`, spatial data, `MyModelImporter`, font metrics and RenderDirect component/updater contracts. MWM vertices, imported tangent handedness and DDS data become persistent native resources. Generic/static groups consume 64-byte hardware instance streams. Cubes retain the source packed rotation, bones, HSV/dither and pattern offsets for stock vertex-shader deformation. Characters use immutable weighted geometry and per-part 60-matrix palettes; bone remapping and triangle partitioning happen once, without animated vertex reuploads. The earlier CPU deformation path remains available to the recording/legacy correctness harness, and is not selected by the production stock renderer.

Transform messages apply their value fields synchronously with the stock world-over-local precedence. Presence flags are cleaned before the pooled packet is reused, including updates for missing actors. Bone and instance arrays are copied; render actors retain no pooled message data. Late camera/pose updates remain pending.

The C++20 engine owns all Vulkan GPU objects. Its versioned C ABI uses opaque context/resource handles and sized structures. Features used by the engine are explicitly queried and enabled: dynamic rendering, synchronization2, timeline semaphores, scalar layouts, BC textures, shader demotion, geometry shaders, extended storage-image formats, independent blending, robust buffer access and depth clamping. Billboard pipelines clamp depth to match Keen's disabled depth clipping; other world pipelines keep their existing clipping state. LDR/PostPP billboard layers retain submission order. Ray query, acceleration structures and deferred host operations are enabled only when the device supports them; creation still succeeds without them. `sevk_get_ray_capabilities` and `sevk_set_ray_options` are sized ABI 1 exports. `enable` 0 builds nothing and dispatches nothing. An enabled shadow frame builds a BLAS per changed supported opaque world mesh, one TLAS from visible rigid/generic instances, and one ray-query compute pass into the sun visibility mask after native shadow resolve and before deferred lighting. Stock lighting consumes the visibility without a duplicate HDR light addition; unsupported geometry and budget refusals retain native coverage. See HardwareRayShadows.md for contracts and regression evidence. That pass is the SE-RT hardware option, not an Anomaly guest draw. Presentation uses binary semaphores. Staging transfers are the default; host image copy is not a dependency. Resource destruction follows completed timeline values. Pipeline caches are persistent. Status samples use CPU snapshots; explicit screenshots may wait for GPU completion.

Vulkan 1.4 host image copying and attachment local read, including broader depth/stencil and multisampled local-read properties, are queried separately and reported as available/absent. They remain unused and disabled. Required-feature checks mask only the ten used bits (0x3C3F); optional absence cannot reject an otherwise compatible device. Preflight diagnostics follow the first compatible device selected by the current adapter bridge.

The world path rasterizes installed Standard/AlphaMasked stock shaders into the source GBuffer formats, with reversed main depth and camera-relative transforms. Material/depth partners share rigid, skinned, generic, cube and deformed-cube streams. Stock LightDir, LightPoint and LightSpot consume GBuffer, published near/far GGX probes and the installed BRDF LUT. Eight quality-sized cascades use stock filtering; sixteen spot shadow/cookie projections bound the shadow budget. Point lights retain conservative tile lists for the nearest 64 local lights. SSAO/HBAO and stock exposure/bloom/tone/FXAA/highlight/chromatic passes now compose the scene. LDR/PostPP billboards and HUD keep their source ordering. PostPP billboards draw on the final output after temporal reconstruction, with composed output depth, so DLAA/DLSS cannot bypass Rich HUD. Generated presents replay that overlay before sprites. See `Postprocessing.md` for the remaining culling/cadence/stereo limits.

The main frame copies objects, instance streams and light lists into persistent mapped buffers belonging to two fenced graphics slots. Each slot's descriptor pool is recycled after its timeline completion. Resource copies and LCD passes collect into a separate asynchronous command batch. Two timeline-owned upload slots retain staging allocations until completion; batches flush at 64 MiB boundaries, with a 64 MiB reusable staging cache per slot. A single oversized resource may exceed that batch threshold. Uploads wait only when a staging slot remains in flight, rather than once per texture/mesh. Pending replacement/removal uses the reserved batch completion value, including copies queued before submission. Minimized frames still flush uploads.

Material emission includes the source environment's `BloomEmissiveness` scalar. Copied stock postprocess layouts now feed histogram/fixed exposure, bloom and Hable tone mapping. Sprite/LCD rendering uses premultiplied linear blending and sRGB attachments, complete 2D DDS mip chains, stock packed geometry precision, and the LCD's separate logical viewport for coordinates/scissors.

The UI path copies sprite/font/scissor commands. Generated textures share the material texture namespace; LCD commands render to native offscreen targets. Full-frame native-size capture copies before presentation, then writes RGBA PNG. Capture storage matches the swapchain format: HDR scRGB uses eight bytes per texel and converts linear half-float RGB to a bounded SDR sRGB PNG preview, leaving HDR presentation enabled. Scaled and world-only capture report their unsupported status rather than silently substituting a different image.

Windows presentation uses the existing HWND and actual monitor modes. Linux surfaces use LinuxCompat's SDL3 owner thread and Vulkan loader. Forwarding guards avoid DXGI device access while Vulkan is active. Pixel size, null-render mode and host presentation readiness are respected. Linux integration checks are compile/signature evidence until tested on an X11/Wayland game host.

Presentation follows the live client extent; the selected resolution defines the logical world/HUD coordinates. Applying Display settings publishes the logical size through the game's main-thread `UpdateScreenSize`, which recreates GUI controls and updates the camera viewport. The game singleton is the static `MySandboxGame.Static` field. Swapchain replacement joins asynchronous presentation, flushes uploads, drains the render timeline and waits for the presentation queue before destroying its semaphores. Native C ABI calls serialize per context: game-thread guest publications and render-thread submissions share queue, command-pool and timeline state. Guest image staging joins the upload slot's retained allocations when uploads are batched.

## Shaders and diagnostics

Native shaders are built by pinned DXC to SPIR-V 1.6 (`vulkan1.3` target) and validated for Vulkan 1.4. Native SPIRV-Reflect checks pipeline descriptor and push-constant contracts. The installed-content compiler service produces content-sensitive cache keys and reflected layout metadata. It does not establish that every installed HLSL permutation has a Vulkan render pass; those ports belong to the remaining parity work.

The installed-content suite captures stock cache generation and runtime geometry/array/impostor/merge-instancing variants. Its versioned catalog separates compilation/validation from native integration and visual acceptance. See `ShaderSuite.md` for the exact scope, legacy exclusions, translation fixes, build command and reflected capabilities. `VulkanShaderLibrary` authenticates the catalog, installed source/assembly and loaded binaries before returning artifacts; it does not silently substitute them into the existing presentation/composition glue. Pulsar reports conversion readiness and pass integration separately.

The independent synchronous stock GBuffer remains a correctness fixture. Production rendering uses the additive world/upload exports on ABI 1, with sized draw and diagnostic structures and copied frame packets. Runtime copies remove DXC's reflection-only Google annotations before driver submission. Startup authenticates the catalog and all forty-four material/depth pipelines, nine environment stages and the stock fullscreen/lighting modules. Twenty-two combinations absent from the vanilla precompile annotations are compiled offline from the same installed shaders and source-backed definitions, then packaged as forty-four supplemental stages with binary/metadata/definition hashes. They require no startup compiler process. Status distinguishes pipeline readiness from observed stock world, instance, skinning, lighting and upload counters.

`MessageCatalog.cs` and `RenderMessages.json` inventory all 147 message kinds from the current decompiled enum and actual dispatchers. Entries distinguish handlers, outbound responses, vanilla baseline no-ops and pending work. Baseline voxel message no-ops do not establish voxel processor coverage. Handler notes record partial semantics. Unknown inputs are reported once per kind with actionable context.

Pulsar Show Status and Write report to log expose selection/recovery, hooks, runtime/ABI, GPU/API/features, validation availability, presentation, resources, shaders, system states, frame counters, compatibility and bounded failures. States are Not implemented, Unavailable, Ready, Active, Verified, Failed and Disabled. Frame evidence is explicit; Release builds retain status. Reports refresh at most once per second without querying the GPU from the simulation thread.

## Remaining parity order

The converted core material/GBuffer/lighting passes, GPU instancing/skinning and asynchronous uploads now serve the Creative world path. Keep visual comparison and performance acceptance separate from compilation and draw evidence. The next parity work consumes the same complete recorded runtime shader catalog.

1. Voxel actors/processors, clipmaps, materials, mining invalidation and LOD; validate an asteroid before planets.
2. Planet streaming, atmosphere, clouds, fog, foliage and weather.
3. Glass, transparent models/decals, OIT, flares and GPU particles.
4. Environment probes, remaining shadows/occlusion, SSAO/HBAO, exposure, bloom, highlights, FXAA, postprocessing, DRS/upscale and applicable stereo paths.
5. Advanced capture, debug views, profiling, reload/reset and complete graphics-settings behavior. Native media/audio implementation and platform acceptance are tracked in [NativeMedia.md](NativeMedia.md).

Existing graphics-plugin ports are subsequent work. No postprocessing or atmosphere omission is counted as visual parity.

## Asteroid clipmaps (Phase #2)

The game voxel clipmap/mesher now uses Vulkan actor/cell/processor implementations. Four stock triplanar/depth pipelines consume copied 24-byte vertices and GPU-normalized material arrays through the existing GBuffer/lighting/shadow path. See [voxel ownership, material layouts and acceptance scope](Voxels.md).

## Planet environments (Phase #3)

Planet clipmaps supply stock spherization constants, infinite reversed main depth and far-frustum visibility. Visible material triples share bounded texture pages. Nine authenticated stock stages provide atmosphere compute/scattering, clouds and grass/pebbles; `environment.inc` binds their reflected contracts with fenced constants, persistent point streams, cached optical-depth LUTs and explicit synchronization. Weather fog/wind updates retain the simulation's original ownership. See [planet contracts, source references and limits](Planets.md). The Phase #3 milestone used ABI 1 with 56 exports. Phase #5 expands the same additive ABI to 80 required exports and ten environment stages, including atmosphere probes. Weather particles use the Phase #4 bridge; broad exposure/atmosphere visual parity remains under review.

## Transparency and GPU particles (Phase #4)

`transparency.inc`, `decals.inc`, `particles.inc` and `flares.inc` execute authenticated stock glass/decal/billboard/OIT/particle shaders and copied scene packets. Independent blending and robust buffer access are explicitly enabled, and source CPU particle hooks are preflight checked. Persistent slot resources, explicit compute/raster barriers and completed-slot readbacks preserve asynchronous status. See [transparency ownership, contracts and acceptance limits](Transparency.md).


## Probes and postprocessing (Phase #5)

`probes.inc`, `postprocess.inc`, `hbao.inc`, `stock_shadows.inc`, `spots.inc`, `highlights.inc` and `occlusion.inc` own source-selected GPU stages and copied packets. Managed `VulkanResolution` ports the game's DRS heuristic and consumes completed-slot Vulkan timestamps. Offscreen casters remain available for shadows/probes; delayed hidden results require matching scene/camera/depth revisions. Status polling remains CPU-only. The ABI is version 1 with 80 required exports; supplemental material/forward/highlight assets contain 128 stages. See [Phase #5 ownership and acceptance contracts](Postprocessing.md).
