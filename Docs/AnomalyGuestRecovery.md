# Anomaly guest activation and stock shader inputs

The 2026-10-16 repair spans Anomaly's guest compiler/submission path and `Native/src/guest.inc`.

The native bridge accepts b0 layouts up to 256 bytes for owned programs, or the exact 1280-byte stock Frame.hlsli used by the world renderer. Stock frame bytes are copied intact; owned camera render-size fields must never overwrite stock matrix bytes. Typed pack storage buffers are accepted at t7–t13, alongside celestial t1. When no catalog override is present, t10/t11 borrow the current world slot's point-light/tile buffers, including the GPU tile variant. The world retains ownership and retirement. Existing producer barriers and read-only fragment access match the stock deferred-lighting consumer.

Replacing a guest image waits for device users of the old allocation. Anomaly reuses image ids across resizing rather than accumulating abandoned images.

Anomaly now waits for the bound native frame callback before compiling and allocating. It supplies stock/pack include roots and slot defines, retains failures, honors manifest binds/priority, and publishes owned products before consumers. Driver-facing bytes pass through SE-Vulkan's existing `SpirvRuntimeModule.Prepare`. The cached artifact retains reflection annotations; see the Khronos [HLSL functionality](https://github.khronos.org/SPIRV-Registry/extensions/GOOGLE/SPV_GOOGLE_hlsl_functionality1.html) and [user type](https://github.khronos.org/SPIRV-Registry/extensions/GOOGLE/SPV_GOOGLE_user_type.html) extension contracts.
